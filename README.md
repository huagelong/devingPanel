# devingPanel 桌面客户端

本目录是 Rust + GPUI Kit 桌面客户端的开发入口。`webui/` 是页面和交互参照，不作为桌面运行时，也不连接真实 VPS。

## 当前进度

- 多主机批次历史区分“全部完成”与跳过失败主机后的“部分完成”、等待构建与构建中；逐主机展示保存的阶段、健康结果与执行耗时，任务未加载时不伪称等待。读取失败清空旧缓存。已核实失败的暂停目标可经二次确认跳过或同批重试，所有已开始目标结果明确的暂停批次（含跳过后待继续的批次）可显式终止。重试会保留每次任务关联，重新核对冻结材料、目标和远端无项目容器后才创建新任务；本机准备失败后的双 VPS 正向链路、GUI 点击及远端残留拒绝均已在隔离项目验收。真实 VPS 健康失败记录的两个独立数据库副本也已通过 GUI 跳过、终止及历史刷新验收，原审计库和远端资源未改写；这不代替故障发生时的实时 GUI 操作。多主机发布入口仍禁用。

开发者在代码目录根创建的最小清单示例（Compose 的 `web` 服务使用 `image: ${DEVINGPANEL_IMAGE_WEB}`；多构建服务各用独立变量）：

```yaml
version: 2
name: myapp
tag: "{timestamp}"
builds:
  - service: web
    dockerfile: Dockerfile
    image: myapp
    platform: auto
    args:
      NODE_ENV: production
deploy:
  compose:
    files: [compose.yaml]
  targets:
    - group: prod
      host: web-1
```

2026-10-27 v20 连续发布实测：以原 v14 数据库的隔离副本和新建的 `dp4` 测试项目运行三次发布。前两次均有四个服务 healthy，经本机/远端材料核实与人工完成流程后记录为 `checked/complete/healthy`，第二次的上一版本预检指向第一次；第三次仅让 Worker 的 HEALTHCHECK 失败，结果为 `checked/blocked/failed`，前两条任务记录仍为 `complete/healthy`，未自动回滚。本轮未在故障后逐份重新核验这两条的本机归档与远端镜像；后续隔离测试已补上此断言，仍需再次实跑。首次故障注入尝试在任务创建前遇到本机 Buildx 能力检测超时；确认未新增任务后才使用新标识重试。测试结束仅对 `dp4` 执行 Compose down，核实其容器为空；`dp1`/`dp2` 未清理，后者的两个历史镜像仍通过只读检查。隔离测试的 Windows 凭据条目和本机数据库/归档副本已删除，原数据库仍为 v14、10 条任务；VPS 的测试镜像 tag 和私有发布目录暂留供后续核对，没有做全局镜像清理。尚未实测 SSH 中途断线后的人工恢复，也没有回滚执行器。 后续手动复跑的 ignored 集成测试增加隔离 APPDATA/数据库父目录核验、随机高位项目 ID 和远端同名容器/网络/卷预检，避免碰撞已有 `dp1`/`dp2`；故障后历史材料及镜像逐项断言尚未按新增版本复跑。通用远端 down 与凭据清理测试入口已移除，清理须针对实际隔离任务逐项核对。

## 本地运行

先安装 Rust 1.92+ MSVC 工具链、Visual Studio C++ Build Tools（含 Windows SDK）及 CMake。其他平台的系统依赖见 [GPUI Kit 安装说明](https://gpui-kit.com/docs/installation)。

```sh
cargo run
```

代码边界：`src/main.rs` 启动；`src/ui/` 呈现；`src/docker.rs` 和 `src/compose.rs` 负责本地 Docker/Compose；`src/release.rs` 负责发布预检与阶段协调、`src/release_store.rs` 持久化任务阶段，`src/build.rs` 负责本机构建及镜像元数据核验；`src/ssh.rs` 负责经指纹核实的 SSH 能力测试与监控；`src/preferences.rs` 定位本机配置目录；`src/database.rs` 管理 SQLite 迁移；`src/project_config.rs` 解析开发者清单，`src/project_store.rs`、`src/host_store.rs` 和 `src/env_store.rs` 保存本机配置。数据库文件为配置目录下的 `state.sqlite3`，schema v11；不保存 SSH 密码、私钥或敏感环境变量值。Build args 和非敏感环境变量值会明文保存，用户不得填写秘密。磁盘与凭据操作在后台执行，不阻塞 UI 绘制。

浏览器原型仍按 `webui/README.md` 启动和测试。桌面视图以 `docs/design/` 与 `webui/test-results/screens/` 为对照；后续页面和交互应逐项比对，不将网页的 hash 路由、本地存储或模拟数据复制为桌面实现。当前桌面端只有 Windows 上的实机窗口与桌面/窄屏截图检查，尚未完成全部页面状态的视觉验收。
