# devingPanel 桌面客户端

本目录是 Rust + GPUI Kit 桌面客户端的开发入口。`webui/` 是页面和交互参照，不作为桌面运行时，也不连接真实 VPS。

## 当前进度

- 已建立原生窗口、224px 侧栏、56px 顶栏、六组导航，以及按 `webui/` 信息层次制作的总览空态。窄窗口改用顶部菜单和 16px 内容边距。总览主机卡片复用可信 SSH 资源采样，显示真实 CPU、内存、运行容器数与磁盘占用；最多三台并发，按完成顺序补位，整轮完成后约 30 秒刷新。离开总览取消采样；60 秒内的上次采样可在返回页面时保留，过期或未取得的数据显示 `--`，不使用原型演示数值。SSH 连接失败、主机配置待核实与采样失败分别处理；Docker 容器查询失败不抹掉 CPU、内存和磁盘采样，容器数单独显示未知。主机配置加载失败显示错误与重试，超过 8 台时卡片区限高滚动。
- 主机、项目、发布与容器页有独立标题、工具区、页签和空态；设置有分类导航，窄窗口可切换分类。项目创建/编辑校验本地代码目录与 Dockerfile；目录可用系统选择器选取，项目列表菜单支持详情、编辑和删除（只删除本机配置）。项目 ID 在改名后不变；更换目录会清空旧 Compose 文件与部署服务，避免同名相对路径指向另一项目；删除级联清理本地绑定。列表、详情与重启读取真实记录。构建配置可保存镜像名、Tag 规则、目标平台和有序 Build args；保存时校验镜像名和附架构后缀的 Tag 长度，发布草稿只读检查本机 tag 冲突，实际构建前必须重查。Build args 明文存储，不能作为秘密通道。
- 主机支持密码或粘贴私钥两种认证配置：非秘密连接信息与认证类型写入 SQLite，凭据内容仅写入系统凭据管理器，SQLite 只保留随机引用。私钥保存时只做安全存储，连接测试时解析未加密 OpenSSH 格式；加密私钥口令尚未支持；较长私钥在系统凭据库中按 UTF-16 长度分片，先存清单，部分写入也可按待清理引用恢复。凭据创建与孤儿清理通过本机文件锁跨进程串行；写入前持久化待清理引用，异常退出后下次启动重试。主机别名、地址、端口、用户和分组可编辑；编辑时同一认证方式留空保留凭据，切换方式须填写新凭据；旧引用按队列安全清理，失败时提示并保留重试记录；地址/端口变化会清除旧指纹信任。删除先标记待处理，再清理本机凭据与配置，不影响 VPS；失败可重试。列表、详情和总览展示真实主机；保存后可手动测试 SSH 登录、Docker/Compose、SFTP 协议握手、系统内核、架构与根目录可用空间。首次或变化的 SSH 主机指纹一律阻断并要求独立核对与显式确认，确认后重连。远端 Docker 操作前解析有效 DOCKER_HOST/DOCKER_CONTEXT 或当前 context，要求本机 Unix socket；后续命令用经校验的 --host 端点显式固定，不能核实则阻断，不把同架构外部 daemon 当作目标主机。列表“在线”只表示最近 60 秒内测试成功，之后自动转为“待复核”。主机详情新增资源监控页签：可信 SSH 读取 Linux `/proc` 的 CPU、内存、默认路由接口网络速率及根目录磁盘占用，列出运行中的容器 CPU/内存；每次采样后约 5 秒刷新，离开页面或切换页签取消采样，失败后停止轮询并提供测试连接/重连。网络默认路由不可读时单独标示不可用，不虚构速率。内置 russh 临时服务器测试了首次/变化指纹阻断、密码/未加密私钥认证、固定能力命令与资源采样；真实 VPS 和 macOS/Linux 待实机 PoC。Windows Credential Manager 已完成隔离的创建、密码轮换、切换到超过单条凭据上限的私钥存储、部分写入清理、编辑元数据、删除及凭据清理冒烟验证。
- 本地 Docker 探测在后台运行并设 5 秒超时，顶栏与总览共享真实检测状态；这不等于构建或部署能力已经完成。
- 容器页可选择真实主机，经已确认指纹的 SSH 连接只读查询 Docker 容器、镜像与 CPU/内存（JSON 行格式白名单解析），停留页面时每次完成后约 10 秒刷新；主机详情可进入对应容器页。容器启动、停止、重启、删除使用固定 SSH 命令和十六进制 ID 校验；停止/重启/删除均二次确认，运行中容器须先停止才可删除。确认时锁定主机地址、端口、认证类型和可信指纹快照；配置变化则阻断操作。执行中目标行显示加载，完成后重新核对列表；SSH 中断或超时且无退出码时明确提示结果待核实，不自动重试。容器日志使用右侧 Sheet 的 SSH `docker logs --follow --tail 1000 --timestamps` 流，保留最近 1000 行、单行限长，滚动暂停自动定位，关闭即取消会话；不落库或写入发布日志。镜像卡片的标题和次操作位置已按 WebUI 对齐；镜像表按 Docker 返回的容器引用数标示"受保护/未引用/待核实"，不据此推断发布保留状态。悬空镜像清理与逐个删除仍禁用，等待发布历史保护以避免误删需回滚的无标签镜像。磁盘清理先从可信主机读取 `docker system df`、悬空镜像大小和未使用网络数量，再按 WebUI 两步确认执行全局 `docker system prune --force`，不清理卷；确认时明确提示它也可能清掉无标签回滚镜像，不能视为受保护的发布历史清理。镜像大小因共享层可能高于实际释放量，实际释放量仅来自远端退出成功后的报告。SSH 中断或超时会提示结果待核实。已用本机 Docker CLI 的隔离只读测试核对 JSON 字段形状；真实 VPS 容器页仍待实机验证。
- 顶栏与“设置 → 外观”共用浅色、深色、跟随系统主题状态；主题偏好只写入本机配置目录的 `devingPanel/theme`，系统模式监听窗口外观变化。语言切换仍未实现。“设置 → 本地环境”显示当前 PATH 中的 Docker CLI 路径、真实检测状态及 SQLite 文件路径，可重新检测并打开所在目录；该路径展示不代表用户可在界面中更换 Docker CLI。
- Compose 子页可使用系统文件选择器添加项目目录内的文件，并将相对路径与顺序保存到 SQLite；首文件必须直接位于项目根目录，新添加的重复、缺失、越界路径被拒绝。文件列表可上移、下移和移除；已保存文件后来失效时，进入 Compose 子页会后台重查并显示行内提示，仍允许逐个移除以修复配置。
- 构建页用本机 `docker compose config --no-interpolate --no-path-resolution --no-env-resolution --format json` 发现服务，核对合并后的目标服务镜像字段为精确的 `${DEVINGPANEL_IMAGE}`；目标服务不能包含 `build`。本地 YAML 先检查 `include`/`extends`（含锚点合并），避免 Compose 合并后丢失这些字段。服务发现和摘要不依赖尚未生成的 `.env`，已用本机 Docker Compose CLI 验证。Compose 页的折叠摘要仅列服务名、脱敏镜像标签、纯数字端口、未展示端口数和卷数量，不显示原始合并配置、环境值、卷路径或解析错误正文；应用内修改文件列表或离开页签会使旧摘要失效，外部编辑文件后需重新展开。摘要会检查所有服务均指定镜像、远端无 `build`、无外部 `env_file`、`label_file`、`credential_spec.file`、`develop`、文件型 configs/secrets 与不可搬迁的 bind mount；选定部署服务后还会核对其镜像引用。完整按主机环境与平台的发布预检未实现，摘要或选中服务都不代表可发布。
- 项目“目标主机”页可按主机组勾选主机、调整发布顺序并保存；数据库校验同组和唯一性，删除主机时自动移除绑定，已绑定多台主机时拒绝单独把其中一台改到其他组。SSH 测试前状态如实显示“未连接”，测试后展示最近结果；编辑草稿在保存前不写入数据库。
- 发布页的待执行配置从真实项目和有序主机绑定读取；项目详情“发布”可进入该项目的草稿。可切换项目，在“更改”对话框内从已绑定主机中选择本次目标、调整顺序，并设置并行度。进度表在执行前如实显示等待状态；发布标识根据规则生成并可在本次草稿中编辑：时间戳用本机时间，`{git-sha}` 在后台从项目 Git 读取；返回发布页保留尚未执行的目标顺序、并行度和标识，项目绑定变动时移除不再绑定的主机。进入发布页后台核对本机 socket 对应的 Buildx default/docker 构建器，只展示其运行节点声明的 linux/amd64、linux/arm64 平台，明确标注“尚未实际构建”；已用本机 Buildx 只读命令核对 JSON 形状。发布草稿后台检查所选目标绑定、镜像名、代码目录/Dockerfile、Compose 文件和部署服务的可搬迁性；还按所选顺序经可信 SSH 测试目标 Docker/Compose、SFTP v3 协议握手、磁盘与 Docker daemon 平台，并与 SSH 主机 `uname` 架构核对，不自动确认未知或变化的主机指纹，再比较项目固定平台与本机 Buildx 声明的平台。远端端点不是本机 Unix socket 时预检阻断；后续命令固定该端点，不随环境变化漂移。切换项目、目标或离开发布页会使旧架构检查失效/取消。这些结果分别标注“本地静态检查”和“SFTP 仅握手/写入待核实”，不等于完整发布预检；已用本机 Compose CLI 验证合法配置与远端 build 拒绝。已在草稿中为每种架构生成独立 tag 并只读检查本机冲突；实际构建前仍须重查；本地 `buildx build --builder default --load` 适配器固定经校验的本机 Docker socket、清除继承的 Docker context/Buildx builder、要求 default/docker 本地节点，并用跨进程构建锁串行化本应用的 tag 重查、构建及元数据核验；提供过滤已知 Build arg 值的逐行日志回调和取消/超时边界（Build args 不是秘密通道，不能保证任意构建输出无敏感值），已用隔离的唯一 tag、无网络 Dockerfile 验证镜像 ID/平台/HEALTHCHECK 及清理，但尚未接入发布执行与实时日志 UI；SFTP 上传适配器已实现客户端生成随机远端临时目录并核对 700 权限、600 文件、按实际发送字节报告进度，关闭并核对大小和 SHA-256 后才报告完成；失败时尝试清理，成功后提供显式清理入口。隔离 russh/SFTP 服务端测试了多块传输、校验及写入失败后的清理；真实 VPS、客户端崩溃后的临时目录恢复清理仍未验证；`docker save` 已与 SFTP 上传串联，但尚未与远端 `docker load`、部署和发布 UI 串联，“开始发布”保持禁用。
- 项目“环境变量”页可按项目通用或已绑定主机编辑 KEY/VALUE。敏感值默认开启、输入默认掩码，系统凭据库保存敏感值，SQLite 仅保存随机引用；重新打开只显示已保存占位，不回填秘密。关闭“敏感”前弹窗确认明文存储，已保存秘密切换后需重新填写。保存时拒绝重复/无效/保留键；主机绑定修改与凭据写入使用同一跨进程锁。取消绑定、删除主机或项目时若秘密清理失败，配置仍已提交但界面会提示待重试，后续启动可继续清理。已用隔离数据目录验证 Windows 凭据写入、读取引用、删除及清理；macOS/Linux 仍需实机验证。发布页对本次选中主机在后台合并通用/专属值、读取凭据并在内存中验证 Compose `.env` 转义；只显示检查状态，不显示变量值。已用隔离 Docker Compose CLI 测试及一次 `run --rm` 临时容器核对特殊字符最终进入容器的值，相关网络已清理。远端 `.env` 上传与历史版本密钥保留尚未实现。
- 已在一台 Debian VPS 上用系统 OpenSSH 客户端验证经独立核对的 ED25519 主机指纹、密码登录、只读命令及 SFTP 登录；尚未用应用内 `russh` 验证真实 VPS 的连接、监控、私钥认证或上传。macOS/Linux 客户端兼容性、完整 Compose 配置语义校验、发布执行、容器操作、除主题外的设置写入和跨平台打包仍待验证。即使已绑定主机，发布入口仍禁用，直到发布预检及执行完成。
- `docs/architecture.md` 中的平台与技术选型仍需按 PoC 验证；能够在 Windows 编译不代表 macOS/Linux 已验收。

本地镜像导出适配器可在核对镜像 ID 与平台后，经固定本机 Docker socket 执行 `docker image save`，将流写入独占的临时归档；取消、超时或失败时删除文件，成功后记录字节数与 SHA-256，归档对象释放时删除文件。已用隔离的无网络镜像实测构建、导出和清理。它已由发布层与 SFTP 上传适配器串联，但尚未接入 UI 发布状态机或远端 `docker load`；应用崩溃后的本地临时归档清理也待实现，不得据此启用发布按钮。

发布层现可串联已构建镜像的本机归档与 SFTP 上传：上传前重新验证目标主机可信指纹、Docker/Compose、SFTP 握手与架构，上传后比较归档和远端返回的大小及 SHA-256，不一致时清理远端临时目录。该适配器尚未从 UI 发布状态机调用，也未实现远端 `docker load`、部署或崩溃恢复；上述归档仍只在正常进程生命周期内自动清理。

## VPS 只读验证（2026-10-26）

在用户通过 VPS 控制台独立核对 ED25519 主机指纹后，使用固定的主机密钥连接 `129.211.23.223:22`。系统 OpenSSH 密码登录、`uname`、根目录 `df -Pk /` 和 SFTP `pwd` 成功；服务器为 Debian Linux `x86_64`，根目录约有 47 GiB 可用空间。远端执行 `docker version` 与 `docker compose version` 均返回 `docker: command not found`。没有上传文件、修改服务器或尝试部署。此测试不等于应用内 SSH/SFTP 适配器验收；该 VPS 安装并启动 Docker Engine 与 Compose 之前，发布预检理应阻断，不能用于镜像传输和部署验证。

## 本地运行

先安装 Rust 1.92+ MSVC 工具链、Visual Studio C++ Build Tools（含 Windows SDK）及 CMake。其他平台的系统依赖见 [GPUI Kit 安装说明](https://gpui-kit.com/docs/installation)。

```sh
cargo run
```

代码边界：`src/main.rs` 启动；`src/ui/` 呈现；`src/docker.rs` 和 `src/compose.rs` 负责本地 Docker/Compose；`src/release.rs` 负责发布前项目静态检查与镜像计划，`src/build.rs` 负责本机构建及镜像元数据核验；`src/ssh.rs` 负责经指纹核实的 SSH 能力测试与监控；`src/preferences.rs` 定位本机配置目录；`src/database.rs` 管理 SQLite 迁移；`src/project_store.rs`、`src/host_store.rs` 和 `src/env_store.rs` 保存配置。数据库文件为配置目录下的 `state.sqlite3`，schema v9；不保存 SSH 密码、私钥或敏感环境变量值。Build args 和非敏感环境变量值会明文保存，用户不得填写秘密。磁盘与凭据操作在后台执行，不阻塞 UI 绘制。

浏览器原型仍按 `webui/README.md` 启动和测试。桌面视图以 `docs/design/` 与 `webui/test-results/screens/` 为对照；后续页面和交互应逐项比对，不将网页的 hash 路由、本地存储或模拟数据复制为桌面实现。当前桌面端只有 Windows 上的实机窗口与桌面/窄屏截图检查，尚未完成全部页面状态的视觉验收。
