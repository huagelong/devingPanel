# YAML v2 多主机批次发布实施计划

状态：进行中。基础能力可交错实施，但验收与开放顺序为 1→7；每项通过验收后更新本文件。发布入口在第 1–6 项完成隔离验收前保持禁用，不得退化成只发布第一台。

## 目标与边界

- 面向开发者已配置 `devingpanel.yaml` 的项目，非技术人员在界面中确认后即可发布整套 Compose 服务到 YAML 指定的全部主机。
- 每个服务/架构只构建并导出一次；同一 Docker daemon 的主机别名不是两个独立部署目标。
- 任一远端结果不明时保留记录、暂停推进，不自动重试、不自动回滚已成功主机。
- 不改动用户现有容器、数据库和 Redis；实机验收使用独立 Compose 项目、隔离应用数据与明确的目标主机。

## 任务与验收

### 1. 批次预检（进行中）

- 一份 YAML 快照解析服务、镜像、目标顺序；绑定主机、可信 SSH 指纹、架构、Docker daemon 身份、环境配置和本机 tag 逐项核验。
- 同 daemon 别名、目标重复、目标配置漂移、平台不支持、变量冲突或缺失环境配置均在创建任务及构建前阻断。
- 执行前重新核对配置摘要和预检身份；预检失败不创建发布任务、不构建或传输。
- 验收：纯逻辑单元测试覆盖目标重排/替换、同 daemon 别名、平台矩阵和配置漂移；隔离环境验证失败时数据库及 Docker 无新增副作用。
- 已有：只读镜像矩阵、目标顺序核对、批次 tag 检查复用矩阵；SQLite v24–v26 的 daemon 级指针及未核实任务约束。新增已接入发布页只读按钮的预检函数，验证可信主机架构、Buildx 平台、环境凭据和镜像变量、tag 冲突及 daemon 别名；按逐主机冻结的 Compose/.env 运行本机 Compose config，核对解析后的自有镜像引用；末尾再次读取全部环境字节并复核项目摘要和主机资料。预检返回同一次读取的 Compose 字节、完整可信主机快照及按目标顺序冻结的环境字节（包含各主机对应镜像引用），逐目标通过现有版本材料 64 KiB 上限校验；不写入数据库或凭据。只读执行前复核接口会再次核对项目摘要、目标顺序、主机资料、架构、Buildx、tag 和 Docker daemon 身份。尚缺执行入口对这些快照的消费、失败零副作用的隔离验收，因此任务 1 仍进行中。

隔离预检故障注入已覆盖第二台缺失敏感环境凭据：使用全新 APPDATA、两台不可达的假主机与独立 YAML v2 项目，运行真实 `preflight_batch`，确认在 SSH 探测/构建/传输前失败，发布任务、批次、目标表数量不变且无共享归档目录。该测试只证明此早期失败分支；同 daemon、平台漂移及构建后健康失败的 Docker/远端零副作用仍需分别验收。

真实双 VPS 只读预检与配置漂移注入（隔离副本）：从已完成批次数据库复制出全新 APPDATA 和项目文件，使用已有可信主机凭据完成新的随机 tag 预检；随后仅修改该隔离项目 Dockerfile.worker，执行前 `revalidate_batch` 明确拒绝。目标顺序为美国 VPS/第一台 VPS，前后容器数 4/19、镜像引用数 4/45 均一致；本机镜像 ID 集合、发布任务/批次/远端 tar 记录数、两个 daemon 当前版本指针均不变。曾因 Docker 镜像清单排序不稳定导致测试误报，改为 ID 排序后用全新隔离副本复测通过。未构建/传输/启动，原隔离项目与旧 unknown 批次未修改；仍需同 daemon 别名、平台/环境漂移等失败分支的隔离验收，任务 1 未完成。

同 daemon 别名隔离实测：从原双主机数据库复制全新 APPDATA/项目，仅在副本中将第二目标的连接地址、可信指纹和临时凭据改为第一台 VPS（仍保留不同主机 ID 与 YAML 名称）；真实 SSH/Docker 身份探测后，批次预检因两个目标属于同一 daemon 而拒绝。该 VPS 的容器/镜像集合、发布任务/批次/tar 数量及原两个 daemon 版本指针前后不变；没有共享归档目录、构建或传输。临时凭据由测试 RAII 定向删除，不修改原主机及凭据。任务 1 仍缺其他平台/变量/环境漂移失败组合。

### 2. 共享构建与归档（进行中）

- 按服务/架构构建、导出各一次；本机归档身份和摘要可用于各目标任务，不重复执行构建。
- 在任何传输前，基于构建镜像 HEALTHCHECK 与逐主机 Compose 有效配置确认所有服务可进行健康核实；若缺健康检查或解析后镜像不匹配，整批停在本机。
- 验收：同架构两台只构建/导出一份，混合架构按实际矩阵构建；故障注入证明构建或健康预检失败时零传输。
- 已有：未开放的本机构建阶段在执行前复核快照，直接遍历唯一服务/架构矩阵，按已冻结的 YAML 构建规格各构建、导出一次，结束后再核对源文件摘要；失败不进入远端阶段，临时归档随所有权释放而清理。构建后现在从冻结的 Compose/逐主机环境字节创建短暂配置目录，调用本机 `docker compose config`（不启动服务），逐主机核对解析后的镜像引用及有效 HEALTHCHECK，拒绝显式禁用、远端 build/扩容；Dockerfile 或 Compose 任一方可提供健康检查。临时配置在调用后清除；已在本机 Docker Compose CLI 上执行一次不启动容器的冻结快照解析测试。共享 tar 现按批次 ID/服务/架构哈希保留到独立 batch-archives 目录，复制时核验字节数/SHA-256；全部归档逐份核验通过且目标仍等待，才原子置为 ready，不持有 SQLite 写锁读取大 tar。构建函数已接入留存与就绪门槛，失败不传输。逐目标传输已有从共享 tar 生成独立校验副本的内部入口；SQLite v28 把经 tar 解析的配置/平台镜像 ID 和归档摘要一起落盘，ready 前再次从校验副本解析并比对登记 ID，逐主机复制时也重复该检查，不依赖调用方提供身份。v27 升级不凭空补录旧 ID，缺 ID 的归档不得进入 ready，未来必须逐次复制/核验，不能只信 ready 时的哈希。静态符号链接/越界目录在写入前拒绝。中断于构建/归档时不盲目重构或删除；在所有目标仍未开始且项目锁可取得时，内部 API 可显式终止该批次，保留待人工核对的残留镜像/归档，再用新 tag 重建；该入口未接入 GUI，未终止的中断批次仍阻断新批次。归档可能占用大量磁盘，目前不自动删除。仍需环境隔离、归档跨目标实测及隔离 Docker 构建/失败零传输验收。

本机真实 Docker 故障注入（隔离 APPDATA）：从独立 YAML v2 Compose 快照构建并导出两份唯一 tag 镜像，故意移除 worker 的 Dockerfile HEALTHCHECK，Compose 也不补该服务健康检查；构建后整栈配置核对返回“缺少有效 HEALTHCHECK”，未登记共享归档、发布任务、批次或远端 tar 意图。测试前后原有两个容器 ID 不变，仅定向移除本轮两个唯一测试 tag。该测试调用与执行器相同的本机构建/健康门槛，跳过远端重新确认与批次创建；同一隔离测试随后把 worker Dockerfile 改为无效指令，确认 web 已导出的临时 tar 随失败释放，worker 没有生成 tag，任务/批次/远端意图仍为空；两个本轮唯一 tag 均定向移除。仍需混合架构和两台 VPS 真实零传输对照，任务 2 未完成。

混合架构本机构建实测：在独立 APPDATA/`FROM scratch` 夹具上按现有批次矩阵分别构建 web、worker × linux/amd64、linux/arm64 四个唯一 tag，并逐份执行真实 `docker save --platform` 与 tar 配置/平台镜像 ID 核对；两台目标各映射本平台两份镜像，四个服务/架构组合均只出现一次。测试结束定向移除四个唯一 tag，本机原有两个容器 ID 不变。该夹具的 HEALTHCHECK 只用于镜像元数据验证、不证明可实际运行健康；尚需把混合架构通过完整共享归档 ready 门槛及双主机运行/失败组合验收，任务 2 未完成。

混合架构共享归档 ready 门槛补验：在全新 `target/isolated-tests/batch-ready-8392808411c54b39891cfe93b8742cd9/` 的 SQLite 与 YAML v2 项目中，用两台不可达的假主机身份映射 amd64/arm64，调用真实本机构建→Compose 有效 HEALTHCHECK 核验→归档留存→`ready` 路径。web/worker × 两平台各构建并登记一次，四条镜像记录的 tar 均为 8,704 字节、64 位摘要及配置/平台镜像 ID，四份本地共享 tar 可按目标平台独立复制和核验；批次 ready，两目标 waiting/无发布任务，本机两容器不变，四个唯一测试 tag 已移除。该测试没有远端 SSH/传输，scratch 镜像只验证健康检查元数据而非运行健康；混合架构跨两台真实 VPS 的部署仍需实际不同架构主机才能验收。

### 3. 批次与逐主机持久化（进行中）

- 保存批次标识、配置摘要、目标顺序、共享镜像、各主机的阶段/结果和关联发布任务；在远端副作用之前持久化意图。
- 重启后区分成功、失败、未知、未开始；同 daemon 的别名沿用同一版本指针，旧单主机记录不伪造批次关系。
- 验收：迁移与崩溃恢复测试证明部分成功和未知结果可追溯，未知状态不被误判为失败或自动重新执行。
- 已有：SQLite v27 新增批次、唯一服务/架构镜像和有序主机快照表。内部创建入口先实时复核源文件、冻结环境字节、tag、可信 SSH/daemon 身份，再以即时事务核对 YAML 项目、目标绑定顺序、可信主机字段及未核实发布/回滚任务，原子写入全部 `prepared`/`waiting` 意图；同一项目只允许一个未结束或待核实批次。活跃批次与单主机发布/回滚互斥；任一批次历史会阻断项目删除及项目 ID 复用，活跃批次还阻断目标主机删除。升级不为旧单主机任务补造批次；落盘重开测试检查跨架构镜像矩阵、完整主机身份、目标顺序和等待状态，绑定重排或重复服务失败时不留下半批次。已新增内部批次专用发布任务创建：仅允许 `ready/running` 批次的当前有序等待主机，在同一事务重新核对当前 project_hosts 绑定/顺序、daemon/平台/镜像引用及已登记的共享归档摘要，创建发布任务、材料意图并关联目标；普通单主机创建仍被活跃批次阻断。内部目标本机准备函数现消费冻结的 Compose/环境字节，原子关联目标任务并将材料写入系统凭据管理器；每份共享 tar 重新复制、核验并保存在该任务的历史归档下，停在 built 阶段且未上传。任务在 built/building 阶段中断可持项目锁显式按本机准备失败关闭，进入 uploading 后不得使用该入口。凭据保存失败即使有残留也明确是本机失败而非远端未知；在系统凭据管理器的 prepared 清理完成前，禁止跳过/终止。后续目标准备仅重新远程探测当前主机，已健康的先前主机离线不阻断本机准备；全部目标的本地配置/环境仍逐项复核。SQLite v30 按目标保存冻结 `.env` 字节的 SHA-256（不存明文）；重新确认、每次目标准备和目标发布任务的数据库事务均要求当前凭据重建的字节摘要与当初冻结值一致。旧 v29 批次缺摘要不补写、不直接继续；环境变化时显式终止全部已核实的剩余批次并使用新 tag 新建。跨重启仍须用户重新确认，不能自动执行后续主机；未开始目标的中断批次可显式终止但不会自动删归档；共享归档已登记摘要、镜像 ID 和就绪状态，目标版本独立材料/归档准备及主要结果迁移已接入；内部远端分段执行已实现；重启后可从持久化批次矩阵/主机身份重建候选预检，重新读取当前环境、与原批次摘要比较、核验归档并要求用户再次确认，绝不自动沿用丢失的秘密快照。该重新确认入口及完整中断恢复尚未接入 GUI，也未进行多主机 VPS 验收。

### 4. 顺序批次执行（进行中）

- 先只实现并行度 1：逐主机传输、核验、加载、启动 Compose 全部服务并确认健康；上一台健康后才开始下一台。
- 一台失败或未知时暂停后续目标；保留远端临时归档核对线索，不自动回滚已成功主机。
- 验收：两台隔离目标成功链路及传输失败、启动未知、健康失败注入；未启动目标保持未开始。
- 已有：SQLite v29 给批次目标的每份远端临时 tar 预留随机路径、大小、摘要及 reserved→uploaded→loaded→cleaned 记录；SFTP 前先落盘意图，上传结果未知时保留路径和任务阻断，不自动重试。内部单主机分段入口已串接已保存的目标 tar、远端加载、Compose/.env 快照上传、所有服务配置校验、整栈启动和健康核实；每段重新核对任务、批次、可信主机/daemon 身份，启动结果不明时阻断，健康后仍需独立人工确认。内部顺序协调器接受用户确认时的完整预检快照（而非仅比较项目摘要），按 YAML 目标逐台调用共享构建、目标材料准备、预留上传、远端加载、Compose 启动/健康核实；每台健康检查通过先停在 checked/blocked/healthy 并返回批次 ID/任务 ID；用户通过现有健康确认入口再次核实并完成任务后，显式继续函数才进入下一台，故障或未知不自动重试/回滚。首轮构建在无远端副作用的确定错误后可终止未启动批次，但保留本地残留供核对。结构化错误返回批次 ID 供后续历史/恢复定位；短暂项目锁竞争只返回可重试错误，不暂停正常批次；失效/未知处置 GUI、崩溃后的人工重新确认、两台不同 daemon 的隔离 VPS 端到端验收尚缺；内部协调器没有接入发布按钮。

### 5. 失败处置与 WebUI 对齐（进行中）

- 批次总结果及逐主机表展示顺序、架构、阶段、健康、耗时和操作。仅对已核实状态开放重试、跳过继续和终止；未知状态先只读核实。
- 界面遵循 `webui/` 发布页的视觉层次、状态色和窄屏布局，不另造一套设计。

  ```text
  web-1      健康检查     成功          详情
  web-2      镜像加载     待核实        核实
  web-3      等待         未开始        —
  ```

- 验收：真实界面操作覆盖确认、暂停、核实、跳过、终止及历史刷新；禁用按钮不可触发副作用。
- 已有：发布进度总览沿用 `webui/` 的状态结构，新增只读“核对批次目标”按钮，展示目标/材料预检成功/失败及目标与镜像份数，明确有效 HEALTHCHECK 尚待构建后检查；点击不会创建批次或部署，切换项目/tag/目标/环境及离开页面会取消并清除快照。隔离 GPUI headless 测试点击不可用按钮并确认无弹窗/任务。批次历史已读取 v27+ 持久化矩阵及有序目标快照，以与 WebUI 发布表一致的表头展示主机、架构、状态、任务短 ID 和健康/待核实/未开始汇总；重启后只读可见。隔离 GPUI headless 测试已渲染部分成功/等待批次卡片。批次初始执行和其余未知阶段核实 UI 尚缺，仍未做真实 Windows 像素对照。
