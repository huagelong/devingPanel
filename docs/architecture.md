# devingPanel 技术架构设计（M1）

> 状态：方案草案，待平台 PoC 与决策确认；依据 `docs/requirements.md` 及 `docs/design/00-overview.md`～`06-settings.md`。本文面向正式桌面客户端；`webui/` 是交互原型，不是运行时实现或 S3 后端。

## 1. 目标、边界与阻断项

使用 Rust 编写 Windows、macOS、Linux 的原生 GUI 客户端，以 GPUI Kit 实现界面。本地 Docker 完成构建；VPS 仅运行 SSH、Docker Engine 和 Compose 插件，不安装 agent，不开放 Docker TCP 端口。默认通过 SSH 传输镜像，可选外部 Registry。主机/项目配置及发布历史留在开发机 SQLite；客户端不提供 Web 服务、CLI 或 CI/CD 编排。

**平台决策（2026-10-25）：**macOS 最低版本为 15+，与 GPUI Kit 当前安装要求一致；Windows 为 10+，Linux 面向主流 X11/Wayland 桌面。三平台仍须分别实机运行、打包验收，而非只通过交叉编译。来源：[GPUI Kit 安装说明](https://gpui-kit.com/docs/installation)（查阅于 2026-10-25）。

```
开发机（GUI / SQLite / OS 凭据库）
  |-- 本地 Docker CLI --> build / save / push
  |-- SSH/SFTP --------> VPS A / VPS B / ...（Docker + Compose；无 agent）
  `-- HTTPS -----------> 可选 S3 / S3 兼容服务、可选 Registry
```

## 2. 技术栈与代码边界

| 层 | 方案与职责 |
|----|------------|
| 桌面呈现 | Rust + GPUI Kit：导航、表单、任务进度、日志、锁屏、多语言及主题。按照页面设计复刻信息层次与语义 Token，而非直接复用 HTML/Tailwind/shadcn 实现。 |
| 应用服务 | 发布协调器、主机管理、容器/监控、清理、备份/恢复；GUI 只提交意图并订阅状态，不直接运行命令。 |
| 外部适配 | 本地 Docker/Compose 子进程；SSH 命令与 SFTP；SQLite；操作系统凭据管理器；S3 HTTPS；系统文件选择器。用小接口隔离副作用，便于模拟测试。 |
| 数据与密钥 | SQLite 存非秘密配置、凭据引用、发布记录和审计元数据；操作系统凭据库保存秘密值；版本化非秘密 Compose 快照及引用留在客户端应用数据目录。 |

建议先用单个 Rust package 按 `ui`、`application`、`domain`、`infrastructure` 模块分层，不预建多 crate / 插件系统。核心状态使用强类型枚举和显式结果，UI 本地化仅作用于展示层。GPUI Kit、GPUI 底层版本一起锁定并经三平台验证后升级；SSH、SQLite、S3、凭据库与密码学库的具体 crate 先做 PoC，再锁版本，不在此承诺未经验证的 API 或跨平台行为。

客户端异步任务在后台运行，发送有界进度/日志事件给 UI；UI 主线程只更新视图，不执行阻塞 SSH、数据库、Docker 或加密操作。每个任务有稳定 ID、取消标记、超时和当前阶段；长日志限量显示，持久日志脱敏并限额。窗口切换不取消发布。关闭窗口时如有运行/待核实任务，要求确认；进程意外退出后的重启按持久记录重新核实，不能假装原任务仍在后台运行。对同一项目/主机的部署、回滚和清理加互斥，避免竞态；监控读取可并行。退出后没有定时任务，下一次启动/重连补做清理检查。

## 3. 本地数据、凭据和审计

SQLite 以事务迁移 schema，使用不可变 ID 关联主机、组、项目、绑定顺序、Compose 路径、非秘密变量/设置、任务、每主机阶段及发布版本。版本记录包含架构、不可变镜像标识（构建 tag 与可取得时的 digest）、目标服务、Compose 快照位置、环境键与历史秘密引用、状态和耗时。发布中先持久化意图，再进行外部副作用；每阶段结束记录结果。数据库不保存 SSH 密码/私钥内容、Registry/S3 密钥、敏感变量值、备份密码或锁屏密码。

以 OS 凭据库作为敏感值主存储：Windows Credential Manager、macOS Keychain、Linux Secret Service。SQLite 仅保存随机凭据 ID，不从名称拼装秘密值。私钥路径和明文私钥的管理、Linux 无 Secret Service 时的失败提示必须在 PoC 中明确；不允许回退到 SQLite/文件明文。历史环境变量按版本保存秘密引用，保留/清理和删除配置时按引用可达性回收；OS 凭据写入与 SQLite 事务无法原子提交，失败时补偿清理孤儿引用，绝不静默丢失旧版本材料。用户删除/修改当前配置不应破坏尚可回滚的历史引用。Compose 源文件及版本快照不得内嵌密码等秘密：编辑/发布前明确提示使用受控环境变量；无法可靠自动识别所有字面量秘密，因此不承诺任意用户提供的 Compose 文件都可安全明文快照。

应用数据目录的数据库、非秘密快照及审计文件仅向本机用户开放；本机磁盘加密属于用户系统责任。审计记录时间、操作、项目/主机、阶段和结果，不记录命令行中的密码、`.env`、完整 `docker compose config`、认证 URL 或带秘密的错误正文。外部进程使用参数数组而非 shell 拼接；远端命令固定模板且严格引用参数，禁止用户提供任意执行片段。不得把秘密放入易被进程列表或日志暴露的命令参数；Registry 认证、环境变量及重定向方式须专门测试其泄漏边界。构建参数不是秘密通道，在编辑和备份中明确提示。

## 4. SSH、Docker 与 Compose 适配

首次连接显示 SSH 主机公钥指纹并要求显式信任；以后严格校验，变化则阻断直至用户核对并重新授权。测试 SSH 登录、远端 Docker 权限、Compose 插件、主机架构、磁盘空间和必需工具。密码/密钥认证均要覆盖 Windows、macOS、Linux；不启用无条件信任、关闭指纹检查或自动接受变更。连接可复用，但断线后必须重新验证主机身份。远端以登录用户权限运行，不能默认 sudo。

本地探测 Docker CLI、daemon 与目标平台构建能力。Windows 使用 Docker Desktop；macOS 使用 Docker Desktop/OrbStack；Linux 使用原生 Docker。按实际目标 `linux/amd64`、`linux/arm64` 每种架构构建一次，为每种架构生成不冲突 tag；不支持的目标平台在传输前失败，不移到 VPS 构建。捕获构建日志并脱敏；构建成功后核验平台、镜像引用及健康检查元数据。Docker/Compose 优先用成熟 CLI 的机器可读输出，不解析人类可读表格；明确固定所依赖的 CLI 最低版本并在 PoC 验证。百分比仅用于有可靠字节总量的传输；Registry pull 的层进度若无法可靠汇总，展示阶段、日志与耗时，不虚构总百分比。

Compose 文件按配置顺序传给原生 `docker compose -f ...` 合并，不自行合并。首文件在项目根目录、后续文件在项目内；上传时保留相对路径，指定相同 project directory 和固定 project name。目标服务必须使用 `${DEVINGPANEL_IMAGE}`；本地和远端都清除继承环境中的项目键与保留键，用 `--env-file` 指向版本根目录 `.env`，再由受控环境指定目标镜像。按每主机变量解析最终配置，阻止任一远端 `build`，并验证目标服务镜像与本次架构 tag 精确相同。预检拒绝不能安全搬迁的相对 bind mount、其他 `env_file`、本地文件 configs/secrets、`include`/`extends` 及项目外文件；其他服务的镜像须可用。合并配置只在内存中校验，不向日志/预览输出秘密。`.env` 不自动注入容器：Compose 服务仍须显式使用 `environment` 或 `env_file: .env`。

## 5. 发布协调与恢复

```
预检/冻结配置 -> 按架构本地构建 -> 构建后健康检查预检
  -> 每台/每批：分发 -> 校验 -> Compose up -> 状态/健康检查 -> 记版本
  -> 汇总结果；失败暂停、待核实先重连确认
```

发布开始时冻结项目、主机顺序、并行度、变量引用与 tag，运行中修改设置不影响当前任务。构建后、任何传输前，要求多主机目标服务存在有效 Docker HEALTHCHECK（包含镜像或 Compose 定义，不能被 Compose 禁用）；单主机若只有 running 状态，记录“已启动但未验证就绪”，不标健康成功。每台 healthy 后才启动下一台；并行度大于 1 时按固定批次，全部 healthy 才进入下一批。任一失败停止新批次，但已启动的主机执行到可确认状态；允许重试该主机、跳过后继续或终止。无 LB 摘除，不承诺零停机。

默认直连：本地 `docker save` 压缩后通过 SSH/SFTP 传输到远端临时文件，校验完整性后 `docker load`；不足空间、传输中断、校验失败不执行部署。流式/临时文件的具体方案以三平台磁盘与内存 PoC 决定，须能够显示实际传输字节进度并可靠清理临时产物。Registry 模式按架构 push/pull，不在 VPS 留长期明文登录配置；远端临时认证目录权限 700、文件 600，完成/失败清理，崩溃后在不影响活跃任务的前提下补清理并提示可能残留。S3 与 Registry 仅客户端/远端按需访问，VPS 管理流量依旧只经 SSH。

每次发布使用远端独立版本化目录，上传 Compose 和 600 权限 `.env`，以固定 Compose project name 更新同一服务栈。传输文件先写临时路径、核验后再切换/提交，避免将半成品视为可用；`up -d` 不等于成功。单主机轮询容器运行状态；有健康检查则等待 healthy（设计默认 120 秒）；退出、unhealthy 或超时记失败。SSH 断开、客户端崩溃或 `up` 执行结果不明时标“待核实”，重连检查远端 project、目标服务镜像、容器及健康状态，核实前不能自动重试部署、跳过或宣布成功。

回滚按主机独立选择上一“已完成”版本，不以一次多机发布共享 tag 代替逐机记录。仅当上一镜像在远端且本地 Compose/历史秘密材料齐全时可操作；重新上传当次配置并运行同一校验流程，结果可为 healthy 或“已启动但未验证”。失败暂停后续主机，不自动回滚已成功的其他主机。版本数量 N 默认 3、最小 1；N=1 明确警告失去上一版本回滚能力。

客户端在线时每日或启动/重连后检查超额版本；仅按项目/主机的托管版本精确删除，并保护运行中的镜像、保留版本及其他容器/项目引用。删除旧版本远端目录及对应本地快照/秘密引用时维护可重试的逐项状态；清理不能触及待核实或可能仍在使用的材料。全局 `docker image prune` 与托管版本清理是两个入口，前者先展示影响并确认。空间估计允许为未知，不能把共享层逻辑大小当成实际可回收字节。

## 6. 监控与容器管理（P1）

通过 SSH 周期采样主机 CPU、内存、磁盘及网络，识别采样间隔和计数器重置；不可采样时显示“未知”，不把缺测当 0。只在客户端运行时轮询，按可见页面调整频率并设置连接/采样超时；P2 历史趋势保存在本地 SQLite，设置保留期。容器列表、状态和资源指标使用 Docker 机器可读输出；启停、重启、删除与日志流均走 SSH，危险操作确认目标容器 ID，日志流在关闭页面时取消。远端 Docker 权限本身近似主机高权限，界面不声称安全隔离。

## 7. 备份、锁屏与本地化

正式版备份范围为主机、项目及非秘密设置，明确排除凭据值、环境变量值、build arg 值、主机信任、历史/回滚材料、镜像、卷及本机语言偏好。导出前构造白名单 DTO，拒绝未知/敏感字段；本地文件和 S3 对象使用同一带版本的密码加密封装。每次独立随机盐和 nonce，使用经审计的密码派生与 AEAD 实现；与现有原型约定对齐的候选为 PBKDF2-SHA-256（600000 次，16 字节盐）和 AES-256-GCM（12 字节 nonce、128-bit tag），格式头/算法/KDF 参数作为认证数据。正式互通测试通过前不承诺原型文件一定可导入；设置密码二次确认、8～1024 字符，仅留会话内存，不落库。旧文件仍需原密码，忘记不可恢复；不做明文降级。

本地导入/S3 恢复先限制文件大小、校验封装、输入原密码、验证认证标签与 schema/引用完整性，再预览并明确确认整体覆盖；提交时再次检查无运行、暂停或待核实发布。使用暂存表/事务原子替换配置，失败不改现有配置；恢复后所有主机重新确认指纹、重配凭据与环境值、核对本地项目路径。历史和缓存与新配置隔离/清空，不能把备份视为部署回滚。文件写入采用临时文件加原子替换；S3 采用 HTTPS、显式 Endpoint/Region/Bucket/Prefix/Path-style，列举/下载/删除仅处理约定前缀内对象，服务端返回不可信，凭据仅在 OS 凭据库。首次实现时要通过实际 S3/兼容服务的连接测试、上传/下载/篡改拒绝测试，不沿用 HTML 原型的模拟记录。

本机锁屏存独立盐和口令验证值，不存明文；启动即锁定，支持手动锁屏和无操作 1～1440 分钟（默认 5 分钟），恢复前台时按单调时间检查超时。改密、关闭或改间隔要求旧密码。锁定时阻断全部 GUI 操作、清理会话备份密码与未提交敏感输入；后台已开始的发布仍完成/核实并持久化，锁屏不等于停机或加密数据库。密码验证与 OS 安全存储可用性须实机测试；不可用不降级。锁屏无法防御本机管理员、进程内存或离线文件修改。

将中文（默认）与英语字符串集中管理，持久化本机语言偏好，切换立即重绘；仅翻译 UI 文案，不翻译项目名、路径、标识、日志及业务枚举，也不改变备份格式。GPUI Kit 主题用语义色/间距组件映射 `docs/design/00-overview.md`，设置按 `06-settings.md` 分独立子页；原型的 hash 路由、DOM/localStorage/Web Crypto 不是桌面实现要求，桌面需提供等价导航/状态和安全行为。

## 8. 验证计划与待确认

| 阶段 | 可验收的结果 |
|------|--------------|
| M1 平台 PoC | GPUI Kit 在 Windows 10+、macOS 15+、目标 Linux 会话启动，字体/输入/文件选择/主题/打包工作。Docker CLI 多架构构建、SSH 密码/密钥+指纹、三平台安全存储和 SQLite 迁移验证通过。 |
| M2 单主机闭环 | 在真实 VPS 构建、直连分发、Compose 合并校验、部署/断线核实、回滚（N>=2）、定期清理与锁屏/加密本地备份测试通过；确认 VPS 未运行客户端服务。 |
| M3 多主机与外部服务 | 三台含混合架构 VPS 顺序/分批、失败暂停/跳过/重试；Registry、真实 S3/兼容服务、监控及容器管理测试通过。 |
| 通用质量门 | 单元测试覆盖状态机/清理保护/备份拒绝，集成测试覆盖 SSH/Compose/恢复；三平台打包与实机 GUI 冒烟、中文/英语及锁屏交互；基准测量空闲 CPU 和常驻内存是否满足需求的 200 MB 上限。 |

待确认/PoC 风险：

1. GPUI Kit 在 macOS 15、Windows 10 和目标 Linux 发行版的打包运行依赖、X11/Wayland 覆盖、字体/中文输入及无障碍能力；不能以编译成功代替实测。
2. SSH、Secret Service、S3、SQLite、密码学与文件选择器的具体库/版本、许可证和最小系统依赖，以小样例验证后固定。Linux 缺少安全存储服务时敏感功能应不可用并给出配置指引。
3. `docker save` 压缩、SFTP 进度和断线后的远端核实要用真实镜像、不同架构及低带宽主机验证空间、耗时与可恢复性；不保证 Registry 拉取有准确整体百分比。
4. 备份加密格式要定稿测试向量及原型互通策略；若不兼容，应明确格式版本和迁移规则，不静默接受明文文件。

需求覆盖：主机 H-1～H-4、构建 B-1～B-5、分发 T-1～T-4、部署 D-1～D-7、多主机 M-1～M-5、监控 S-1～S-4、容器 C-1～C-5、安全 SEC-1～SEC-5、备份 BK-1～BK-4；P2 历史趋势/告警仅预留数据边界，不提前实现。
