# P4 发布执行 / 发布历史 设计文档

> 需求映射：本地构建、Compose 部署、单主机与多主机批次、健康检查、失败核实、发布历史和回滚。项目配置以 `03-projects.md` 为准，保留与清理以 `06-settings.md` 为准。

## 1. 页面目的与入口

侧边栏“发布”、总览“去发布”和项目列表/详情“发布”进入执行页。发布页的“历史”页签列出全部任务；总览最近发布与项目发布历史均链接到对应记录。页面展示当前真实任务状态，不以进度动画代替执行结果。

## 2. 执行页

页头“发布”下有“执行 / 历史”页签。配置栏包含项目、按项目 YAML Tag 规则自动生成的只读发布标识、目标主机及顺序、并行度、[开始发布]；不在项目选择框下重复显示传输方式。发布时使用页面显示的标识，不能在发布页手工修改；规则在项目构建配置中编辑。默认使用项目绑定顺序；“更改”只在本次发布调整目标，不回写项目绑定。单主机默认并行度 1；多主机按持久化并行度分波次。正式多主机 [开始发布] 在 `docs/design/03-projects.md` 所述验收完成前保持禁用，展示明确原因；原型的 P1/P2 演示可展示批次交互，但须标明模拟。

开始前读取项目目录内最新的 `devingpanel.yaml` 并冻结配置快照。若文件缺失、损坏、外部变更未重读、目标主机不唯一或缺少可信指纹/凭据，阻止发布并引导到项目/主机页。检查本地 Docker、构建平台能力、目标主机架构与 Docker/Compose、Compose 文件及合并结果、目标镜像变量、远端禁用 build、环境变量和版本 tag 冲突。任何主机未通过预检时不上传，不在 VPS 构建。Registry 模式还须检查配置、镜像名前缀和登录；传输方式在任务创建时冻结，运行中不可切换。

执行区保持紧凑：配置栏下直接是逐主机表格，表头只显示当前任务状态；有失败、暂停或待核实时在表头附近显示一句可读原因。顶部栏下沿在任务运行时显示细进度条。逐主机列为顺序、主机、状态、阶段、传输进度、耗时、操作；阶段至少区分传输/拉取、Compose 启动、健康检查、完成。传输方式、目标架构、构建前后预检、本地构建和 Registry 推送进度归入下方可展开的构建日志，不在页面中另设进度总览卡片。日志可复制，不记录凭据、环境变量值、完整 Compose 配置或 Registry 令牌。

## 3. 状态与人工处置

成功：有效 HEALTHCHECK 通过。无 HEALTHCHECK 的单机任务显示“已启动，未验证就绪”，不得标为健康成功。失败：展示可读原因和受影响主机；允许在明确失败且结果已知时重试该主机、跳过此台继续或终止，已成功主机不重复构建/部署。SSH 中断、超时、客户端退出或 Registry 推送中断导致远端结果不明时标“待核实”；停止自动推进，不提供直接重试/跳过，先重新连接核对实际镜像、Compose 和容器状态。核实仍不确定时保留待核实，不能用本地推测改写成功状态。

批次终止只取消未开始目标，并等待已进入远端操作的目标得到明确结果或待核实状态；不可把正在执行的远端操作直接写成已终止。每波目标的健康结果逐台可见，故障和未知状态在历史中单独核实。发布中锁定项目、目标、并行度、传输配置及相关导入/恢复操作。离开页面可回到当前任务，任务结束后保留最终结果和日志入口。

## 4. 发布历史与回滚

历史表列为时间、项目、发布标识、结果、目标主机数、耗时、详情。总览、全局历史和项目历史的时间统一显示本地时间 `YYYY-MM-DD HH:mm:ss`，不随界面语言改变格式。项目详情只筛选该项目的不可变 ID，最多每页 20 条，支持上一页/下一页；改名不改变历史归属，删后重建同名项目不继承记录。详情展示发布结果和逐主机状态、原因，并直接展示当时保存的构建日志，支持复制；历史日志不得从当前任务重新生成，旧记录若没有日志须明确提示。目标主机不超过 4 台时展开显示；更多主机默认折叠，展开列表限高滚动，使日志保持易见。镜像引用、架构和阶段耗时收在可展开的技术信息中，不展示没有实际用途的演示审计编号。详情保存发布时的项目名、目标顺序、各主机架构、镜像引用、状态、阶段、原因、日志和材料可用性，当前配置变更不能改写历史快照。历史中部分成功、失败、跳过和待核实要按主机显示。

回滚入口只对有完整本机归档、远端版本目录和历史密钥材料的具体主机可用；先核对主机信任、Docker 身份、镜像及 Compose/环境材料，再二次确认目标版本和影响范围。回滚逐主机执行并记录独立结果，不把回滚当作新构建；材料缺失、主机已删除、历史状态待核实或版本已被清理时禁用并解释原因。回滚结果不修改原发布记录。

## 5. 页面状态与原型边界

加载显示骨架；无项目引导创建项目，无历史显示空态；读取/连接失败显示原因和重试。所有写操作完成后有 Toast，失败反馈包含可读原因。P0 仅展示单主机配置，P1 展示多主机，P2 增加趋势/告警入口。窄屏配置栏换行、表格局部横向滚动，主操作始终可见。

`docs/webui` 使用用户授权的项目目录实际读写 `devingpanel.yaml`，但构建、SSH、传输、健康检查、历史和回滚仍为演示数据，不能证明远端已发生操作。文件句柄不跨刷新保留；桌面客户端另行负责系统凭据存储、发布前重读与发布验收。
