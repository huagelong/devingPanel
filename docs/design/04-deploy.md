## 3. 发布执行页

当前落地范围：开发者维护的 YAML v2 支持单主机发布；多主机已实现顺序及分波次并行协调、持久化历史和人工处置，但正式“开始发布”入口仍关闭。静态检查与可信 SSH 预检通过后，确认会绑定项目文件摘要、目标身份、镜像计划及并行度；变化则拒绝执行，执行器仍重新预检。同波次共享本机构建、各主机独立传输与启动完整 Compose 栈；健康目标需逐一人工确认，已核实失败目标可显式跳过或保留旧任务记录同批重试，未知结果阻断下一波。界面不展示原始构建输出或 Compose/环境内容。双 amd64 VPS 的顺序、并发故障及崩溃恢复，和三台 amd64 VPS 的两波次健康发布已隔离验证；三目标成功续发以及预传输失败目标跳过后的历史页点击都已实际触发第三台远端执行。VPS3 的 QEMU ARM64 客机已与 amd64 VPS 完成共享构建、逐平台归档和双目标四服务健康发布，按用户新口径满足混合架构验收。原生 Windows 宽窄屏视觉和真实点击对照仍未通过，不能开放多主机按钮。历史阶段记录与剩余门槛见 `docs/plans/multi-host-release.md`。

历史页的受控单主机回滚入口现先做只读预检，展示源/目标任务、主机、逐服务镜像和待从本机 tar 恢复的镜像数；确认后绑定目标版本、预览时的源容器集合与目标镜像缺失集合，再由执行器重查，变化则拒绝执行。执行期间展示固定阶段、刷新历史；失败和 SSH 不确定结果阻断且不自动重试。GUI 回滚仍待隔离 VPS 与实际窗口验收。多主机批次回滚、任意阶段的自动解除或重试不在当前实现范围。

回滚预览与创建复用 SQLite 资格检查；执行结束的历史刷新若遇到同范围的加载中请求，会在其完成后再读取一次。最终健康完成记录写入或核对失败时标记待核实，不留下已退出执行器却仍显示 `checking/running` 的任务。开发版窗口验收只能使用隔离的 `APPDATA`，不能再次直接启动在用户默认数据目录上。

隔离 VPS 验收记录（2026-10-27）：真实测试已改用 GUI 对应的带摘要发布和预览/确认回滚 API。首版四服务健康并二次确认完成；第二版在上传前 SSH 连接超时，留下 `uploading/unknown` 阻断，没有执行回滚或自动重试。只读远端观察显示四服务仍 healthy，但不能以健康状态推断第二版已发布。该高位随机项目及隔离数据库、远端材料保留供人工核对；GUI 点击链路和确认回滚尚未完成实机验收。

传输阶段中断的人工处理：仅 `uploading/unknown` 尚未进入 `docker load` 或 Compose，且本机项目锁空闲时可弹窗确认只读核实。重新获取同一 Docker daemon 的已确认当前健康版本，先按历史凭据快照校验远端 Compose/.env 文件 SHA-256，再计算该历史配置逐服务 `docker compose config --hash '*'`，与当前容器的 Compose 配置哈希标签逐项对比；同时检查服务数量、服务名、配置镜像、不可变镜像 ID、运行状态及 HEALTHCHECK 全部匹配。在 SQLite 即时事务中重查任务阶段、主机/daemon 快照与当前版本指针，再将中断任务记为 `checked/failed` 并插入独立审计。远端临时 tar 可能残留，不能在此入口自动删除；加载及之后的未知阶段继续阻断。此入口不重试发布、不回滚，也不把旧容器健康误报为新版本完成。远端 Docker 被外部进程并发修改时，SSH 观察与数据库提交仍无法原子化；需独占维护窗口进行人工确认。

隔离 VPS 续测：`dp1210048068` 的传输未知任务经同一批容器 ID 的哈希、镜像与健康核对后显式关闭，审计写入成功；新 tag 的 B 版随后健康完成，使用 GUI 同款预览及确认参数回滚 B→A 成功。隔离数据库中的当前指针回到 A，远端四服务继续 healthy 且配置哈希匹配 A。此为受控后端路径验收，未证明真实 GUI 点击或窗口视觉符合 `webui`。

后续正向 headless GUI→VPS 验收：严格限定已有高位隔离项目，并在 `AppView::new` 前确认隔离数据库无全局待清理凭据或构建前遗留任务；核对主机地址/端口/账户/指纹、Docker endpoint/daemon、旧版四服务与历史 Compose 配置哈希。GPUI 测试窗口实际点击“开始发布”与“确认开始发布”，等待协调器正常结束，核对新版本为 `checked/complete/healthy`、远端四服务健康且当前指针前移。仍缺 Windows 实际像素验收。

正向 GUI 回滚续测：显式固定源 C、目标 A 的任务 ID 与逐服务镜像引用/ID 摘要，在 headless GPUI 历史页实际点击“检查并回滚”，重新核对弹窗 C→A 及候选指针，然后点击“确认执行回滚”。隔离 VPS 回滚为 `checked/complete`，当前指针回到 A，远端四服务 healthy 且与 A 的 Compose 配置哈希一致。此为按钮→预检→执行的端到端验收，不包含真实 Windows 像素截图。

历史页主视图按 WebUI 原型改为横向可滚动的表格：时间、可选项目列、发布标识、目标主机数、结果、耗时、详情/回滚操作。任务 ID 和核实/材料/人工处理控件保留在点击“详情”后的扩展卡片中，不再默认堆叠所有发布任务；回滚任务作为独立记录展示。SQLite v23 增加独立的 `execution_finished_at`，只在明确失败或健康核实落盘时记录；结果不明不推断远端结束时间，日后人工确认/复核不延长执行耗时。升级前数据不反推结束时间，缺失、执行中或结果不明显示 `—`；运行但尚未验证就绪不标成失败。GPUI 隔离 headless 测试覆盖表格详情展开/收起，仍需真实窗口与 `webui` 像素比对。

发布执行页单主机进度表从协调器固定格式的 `镜像传输 sent/total 字节` 事件提取当前镜像传输百分比，按整数百分比节流；每份镜像开始时清除上一份进度并重置，非传输阶段显示 `—`；切换项目也清除上次发布身份和进度，避免旧状态串入新草稿。本机单调时钟更新当前执行耗时，结束时冻结。原始构建输出不作为阶段事件展示；异常断开时保留阻断，提示人工核实并刷新历史。

版本保留只读计划现以 `project_current_version` 指针及 `release_predecessors` 为依据：只有已确认健康且同一 Docker daemon 的指针任务列为当前保留，其真实前驱列为上一版本；回滚后时间上较新的完成任务不冒充当前版本，归为待人工核对历史。缺指针、指针身份不符及其他 daemon 的历史一律不确定且不进入自动清理候选。远端容器仍需实时核对；该判定不删除本机归档或远端镜像。

项目历史新增本机 tar 只读容量预览：只对无待核实任务、指针有效且归类为更早历史的任务核对每份归档记录、实际字节与 SHA-256；缺失/校验失败单独提示，不合计为可核验容量。当前指针、其前驱、其他 daemon 或身份不确定版本均跳过。隔离高位项目只读实测为两条历史归档完整。该预览不提供删除许可，不等于远端 Docker 层可释放大小；设置页“自动清理”和保留数仍未生效，清理按钮禁用。

定向删除安全门槛：不能先按路径核验再按同一路径删除，因为外部进程可在两步之间替换目录/文件；多镜像任务部分删除后必须能按逐服务审计重新核对并继续或停止，审计完成前不得解除阻断。初版删除实现未通过这两项审查，已撤回，不创建 v24 清理表或暴露按钮。当前只读归档核验及回滚副本额外拒绝符号链接、非普通文件和越界路径；实际删除仍需文件/目录句柄绑定的实现与隔离验证。

多主机 YAML 在当前阶段只读展示预设目标和各主机等待行，执行按钮保持禁用；页面明确提示尚无批次协调器，不会把单主机内部函数偷偷当成全项目一键发布。隔离 GPUI 测试验证多目标警告可渲染、禁用按钮点击无弹窗，恢复单主机后确认流程仍可用。

批次规划的第一段已实现为只读矩阵：同一份已验证 YAML v2 快照用于目标、服务和镜像规划，重新解析当前主机绑定并逐项核对目标 ID/顺序，拒绝同数量重排或替换；单主机协调器也从已读取的同一份 YAML 规划镜像。发布页复用矩阵引用检查本机 tag 冲突，不再独立重读 YAML。根据 `builds` 和可信主机预检平台，把每个服务/架构镜像引用只规划一次，再按 YAML 目标顺序映射到各主机；同架构目标复用相同引用。矩阵检验目标唯一、服务/架构映射唯一及固定平台可用性。UI 展示构建份数与主机分配，批次执行仍禁用；后续需共享本机构建与归档、为每台主机分别持久化意图及健康结果，并处理部分成功/未知结果，不可直接循环单主机协调器。SQLite v24 将旧的项目级当前版本指针原样迁移到项目/daemon 联合键，并按 daemon 更新健康发布、受控回滚和保留判定；不推断别的 daemon 的当前版本。同 daemon 主机别名共用指针；上一健康版本、发布健康确认与回滚候选的最新发布检查也仅比较同 daemon 的任务。SQLite v25 将未核实发布任务唯一约束改为项目/daemon，同 daemon 只允许一条；缺 daemon 身份的旧任务继续阻断整个项目。SQLite v26 保存回滚源 daemon 身份，将未核实回滚约束和发布/回滚互斥检查也限制到同 daemon；缺身份的旧回滚仍全项目阻断。共享构建和顺序执行已有未开放的内部阶段；发布页按 WebUI 进度总览增加只读“核对批次目标”，显示目标/材料预检结果和构建后健康检查待核验提示，项目/tag/目标/环境刷新或离开发布页会取消并清除旧快照。多主机开始发布仍禁用；发布/项目历史增加只读批次与逐主机表，展示已确认健康、待核实、失败、跳过与未开始状态。批次人工处置 GUI 与双 daemon 隔离验收尚未完成；详见 `docs/plans/multi-host-release.md`。

### 3.2 状态机

单台主机状态：`等待 -> 传输中 -> 部署中 -> 健康检查中 -> 成功 | 失败`。
SSH 断开且无法确认远端结果时为`待核实`，不能归类为成功或失败。
执行前先持久化任务意图与非秘密配置摘要、目标主机/指纹快照；每个外部副作用开始前写入阶段，结束后再推进。`running`、`unknown`、`blocked` 任务阻止同项目重复开始及项目/主机删除或修改连接；任务创建与删除检查共用 SQLite 即时写锁。客户端异常退出后不根据旧阶段自动重跑，须重新核实远端。开发者 YAML/Compose/Dockerfile 或旧项目数据库配置变动会使预检失效，构建后再重读当前配置。配置摘要不能代替当次 Compose/环境材料；v16 已保留有限的本机材料，但完整版本保留和回滚仍未实现。

已接入的暂存阶段在本机内存中读取当次 Compose 与合并后的 `.env`，构建前校验可上传的相对路径并把 Windows 路径分隔符映射到远端 POSIX 路径；映射后远端路径重复则拒绝，避免覆盖。正常中文、空格和单引号文件名须安全引用，不做 ASCII-only 缩减。经可信 SSH/SFTP 上传至 `$HOME/.local/share/devingpanel/projects/<id>/releases/<task-id>`；目录 700、文件 600，核对大小与远端 SHA-256。部分 `mkdir` 成功后超时也尝试清理随机目录；部署前失败时逐文件删除并逐级 `rmdir`，不递归删除未知内容；成功后保留本次版本目录供后续 Compose 执行与回滚。暂存后在可信主机上用明确的镜像引用和当次 `.env` 执行 `docker compose config --format json`，只在内存中核对目标服务镜像和所有服务的镜像/构建字段，不记录可能包含秘密的原始配置或远端错误正文。内部单主机协调器随后用已核验归档的配置/平台 manifest ID 复核远端镜像 tag（不要求其等于本机镜像 ID），仅对单副本的选定服务执行 `up -d --no-build --pull never --no-deps <service>`（多副本在预检中拒绝），不改变其他服务；依赖服务须预先可用，否则目标服务可能无法就绪。以新的 SSH 连接只读检查目标容器是否使用该归档中的镜像 ID、运行和 HEALTHCHECK 状态，最长等待 120 秒。无 HEALTHCHECK 仅标为“运行中，未验证就绪”；断线或启动超时不自动重试，保留“待核实”。核实为失败时也保留阻断直到有人工处理入口，避免部分部署后盲目重试。完成历史材料与人工恢复入口前不能报告一键发布成功，GUI 入口仍禁用。

回滚规则：每台主机独立记录已完成版本（"健康成功"或单主机"已启动但未验证"），版本包含不可变的镜像标识、当次 Compose 文件、环境配置快照（敏感值在系统凭据管理器以版本为单位存储，仅存引用于 SQLite）。回滚所需材料以客户端本地保存为准，执行时重新上传 Compose 并按密钥引用重建 `.env`，不依赖远端旧目录。按钮只对有上一已完成版本、完整历史材料且远端镜像存在的主机可用；保留数 N=1 或历史材料已清理时禁用并说明不能回滚。部分发布成功后默认只选已更新主机，每台显示其自己的目标版本，不能用单个 tag 概括所有机器。回滚复用部署及状态检查流程，目标版本本身未配置 HEALTHCHECK 时仍展示未验证警告；任一主机失败暂停后续回滚，保留逐台结果和重试/终止入口，不声称全部已恢复。密钥丢失或材料不全时禁用并解释原因；当前运行镜像与保留数内的版本不得被清理（D-6/D-7）。
