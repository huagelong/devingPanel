# P4 发布执行 / 发布历史 设计文档

> 需求映射：B-2/B-4 构建、T-1/T-2/T-3/T-4 分发、D-2/D-4/D-5/D-6 部署、健康检查、历史与回滚、D-7 历史清理、M-2/M-3/M-4/M-5 多机滚动发布

## 1. 页面目的

承载核心流程：选择项目与目标主机 -> 一键"构建、推送、部署"；实时展示全流程进度；支持失败处理与回滚。

## 2. 入口

- 侧边栏"发布"；项目列表/详情的 [发布] 按钮；Dashboard [去发布]。

### 3.2 状态机

单台主机状态：`等待 -> 传输中 -> 部署中 -> 健康检查中 -> 成功 | 失败`。
SSH 断开且无法确认远端结果时为`待核实`，不能归类为成功或失败。
状态色：等待 = muted，传输/部署 = info，健康检查中 = warning，成功 = success，失败 = destructive。
目标 [更改] 打开主机选择 Dialog：只列项目绑定的同组主机，支持勾选与上移/下移排序；开始发布后锁定。开始发布时先按目标架构在开发机构建：单一架构构建一次，混合架构每种架构各构建一次；成功后、任何镜像传输前检查多主机的健康检查条件。不能在构建前仅凭 Compose 中没有 `healthcheck` 就禁用 [开始发布]，因为 HEALTHCHECK 也可能定义在 Dockerfile 中。

| 规则 | 行为 |
|------|------|
| 逐台执行 | 默认并行度 1：第 N 台"成功"后才进入第 N+1 台（M-2） |
| 并行度 > 1 | 按用户排序分批；本批全部健康检查通过后才开始下一批；任一台失败时不再启动新批次，但已开始的任务继续至可确认状态，显示逐台结果 |
| 构建失败 | 全部主机保持"等待"，日志区 destructive 提示失败原因，无主机被部署 |
| 构建后预检失败 | 通过本地镜像元数据和合并后的 Compose 配置检查有效 HEALTHCHECK（包括 Compose 显式禁用的情况）；若多主机缺少健康检查，提示在 Dockerfile 或 Compose 添加，所有主机保持"等待"且不传输。按目标主机环境解析后的目标服务镜像 tag 不匹配时同样终止上传 |
| 传输失败 | 显示网络/认证/空间等原因；[重试该主机] 重新传输并核验文件，成功才部署，不重新构建镜像 |
| 部署失败 | 核实远端容器及 Compose 状态后，允许重试该主机；若状态不明，显示"待核实"并暂停，不盲目重跑 |
| 失败默认 | 暂停后续批次；用户可 [重试]、[跳过该主机继续] 或 [终止]，跳过后剩余主机继续按原顺序和并行度执行 |
| 终止 | 确认后不启动新任务；已在运行中的部署完成状态核实后展示，已成功主机不自动回滚；如各主机均有可用历史版本，显示 [回滚已更新主机] |
| 健康检查 | 等待 Dockerfile 或 Compose 定义的有效 HEALTHCHECK 变 healthy（120s 超时判失败）。单主机无 HEALTHCHECK 时只能确认容器 running，结果标注"已启动，未验证就绪"；多主机缺少 HEALTHCHECK 在本地构建后、传输前阻止发布 |

### 3.3 发布完成

顶部显示结果条：全部健康 success 背景（success 10% 透明度）"发布成功，耗时 1m24s"；单主机仅运行但无 HEALTHCHECK 时 warning 背景"已启动，未验证就绪"；部分失败 destructive 背景"2/3 成功，web-3 失败"；存在待核实主机时明确显示"结果待核实"，不计入失败或成功。发布历史将"健康成功"与"已启动但未验证"分别记录，后者虽不能宣称健康，仍算一次已完成部署并可参与版本保留及回滚。

## 4. 发布历史页（发布页 Tabs: 执行 / 历史）

```
Card Table
列: 时间 | 项目 | 发布标识(mono) | 目标主机 | 结果 Badge | 耗时 | 操作
操作: [详情] [回滚]
|-- 详情: Sheet 右滑 (sm:max-w-2xl): 每台主机的架构、实际镜像 tag、各阶段耗时、失败原因、审计信息
|-- 回滚: Dialog 显示所选主机各自的"当前版本 -> 上一已完成版本"和可回滚状态
|           [确认回滚] 后逐台恢复对应镜像 + Compose + 环境配置并健康检查
```

回滚规则：每台主机独立记录已完成版本（"健康成功"或单主机"已启动但未验证"），版本包含不可变的镜像标识、当次 Compose 文件、环境配置快照（敏感值在系统凭据管理器以版本为单位存储，仅存引用于 SQLite）。回滚所需材料以客户端本地保存为准，执行时重新上传 Compose 并按密钥引用重建 `.env`，不依赖远端旧目录。按钮只对有上一已完成版本、完整历史材料且远端镜像存在的主机可用；保留数 N=1 或历史材料已清理时禁用并说明不能回滚。部分发布成功后默认只选已更新主机，每台显示其自己的目标版本，不能用单个 tag 概括所有机器。回滚复用部署及状态检查流程，目标版本本身未配置 HEALTHCHECK 时仍展示未验证警告；任一主机失败暂停后续回滚，保留逐台结果和重试/终止入口，不声称全部已恢复。密钥丢失或材料不全时禁用并解释原因；当前运行镜像与保留数内的版本不得被清理（D-6/D-7）。

## 5. 状态

- 加载：配置条 Skeleton。无项目：EmptyState"先创建项目" + [新建项目]。
- 发布进行中切换页面：侧边栏"发布"项显示 info 色小圆点，顶部栏全局进度条（h-0.5, info 色）。
- 从历史或项目页进入时带上发布记录/项目选择；运行期间配置锁定，避免改变目标主机或发布标识。
