# P3 项目列表 / 项目详情 设计文档

> 需求映射：B-1 项目关联、B-3 构建参数、D-1 多 compose 文件、D-3 环境变量（SEC-4 写入远端 .env 权限 600）、M-1 绑定多主机

## 1. 页面目的

管理"项目"：本地代码目录、Dockerfile、compose 文件、构建参数、环境变量与目标主机的绑定关系。项目是发布的最小单元。

## 2. 入口

- 侧边栏"项目"；发布页选择项目。

---

## 4. 项目详情页

### 4.1 布局

```
内容区
|
|-- 页头: 面包屑(项目 / myapp)  右侧: [发布] (variant=default)
|
|-- Tabs: [构建配置] [Compose] [环境变量] [目标主机] [发布历史]
```

### 4.2 Tab: 构建配置

Card 表单：

| 字段 | 控件 |
|------|------|
| 镜像名 | Input (mono)，默认 = 项目名小写 |
| Tag 规则 | Input (mono)，支持 `{timestamp}` `{git-sha}` 占位，默认 `{timestamp}`（不要求项目使用 Git）；生成发布标识后附架构后缀，构建前检查 tag 冲突，绝不覆盖旧版本 |
| 目标平台 | Select: 按主机自动（默认）/ linux/amd64 / linux/arm64；手选平台时所有已选主机必须匹配 |
| Build args | Key-Value 编辑列表（Add row） |
| 部署服务 | Select，从已配置的 Compose 服务中选择一个作为本项目构建产物的目标 |

底部 [保存]；保存后 Toast 反馈。
发布前通过 SSH 读取每台目标主机架构；自动模式汇总所需平台（如 `linux/amd64`、`linux/arm64`），客户端在开发机为每种架构各构建一次，为同一发布标识生成不同镜像 tag（如 `myapp:20261024-120000-amd64` 与 `myapp:20261024-120000-arm64`），同架构主机复用镜像。手选平台不匹配或本地 Docker 无法构建任一目标平台时，在上传前失败并提示本地构建环境需要的能力，不回退到 VPS 编译。Build args 不是秘密传输机制，编辑区提示不要填写密码或令牌。

### 4.3 Tab: Compose

```
Card
|-- 说明行: "支持多个 compose 文件，按顺序合并（后者覆盖前者）"
|-- 文件列表 (可排序，每行):
|    1. docker-compose.yml          [本地路径, mono] [移除]
|    2. docker-compose.prod.yml     [+ 添加文件]
|-- [+] 添加 compose 文件 (系统文件选择器, 可多选)
|-- 预览区: 折叠面板 Collapsible "查看部署配置摘要"
|    内部: 服务名、镜像引用、端口、卷的脱敏摘要 (bg-muted rounded-lg p-4)
```

交互：调整顺序用上移/下移按钮；文件不存在于本地时行内 warning 提示"文件不存在"。

发布约定（MVP）：

- 允许一个或多个位于项目目录内的 Compose 文件，但**首个文件必须直接位于项目根目录**；后续文件可位于子目录。上传时保持相对于项目根目录的路径，开发机与 VPS 均以项目根目录为 Compose project-directory，固定 Compose 项目名，避免每次发布生成新的服务栈。生成的 `.env` 位于该次发布的版本化部署目录根（以项目根目录为基准），`env_file: .env` 因此按首文件所在根目录解析。
- 被选中的部署服务须以 `image: ${DEVINGPANEL_IMAGE}` 引用本地构建镜像；客户端为每台主机设置匹配其架构的 `DEVINGPANEL_IMAGE=<镜像引用>:<发布标识>-<架构>`（直连时为本地镜像名，Registry 模式为完整仓库地址）。其他服务可使用 VPS 已有或可拉取的现成镜像；部署前检查这些镜像是否可获取，缺失且无法拉取则报错，不因缺失而在 VPS 构建。
- `.env` 文件本身不能保证插值优先级：调用本地和远端 Compose 时，客户端必须从继承的进程环境中移除项目配置键与保留键，再以 `--env-file` 显式指向本次版本化根目录的 `.env` 提供项目值；仅 `DEVINGPANEL_IMAGE` 由受控进程环境设置为该主机预期 tag，不能从用户环境继承。构建前与远端 `up -d` 前分别解析最终配置、确认目标服务 `image` 精确等于该主机的预期 tag；配置原文可能含密钥，只在内存中校验且不得记录到日志。
- 发布前在每台主机对应环境变量下验证合并结果：所有服务都不得包含 `build`，否则阻止发布，避免 VPS 编译。仅上传 Compose 文件和客户端生成的 `.env`；普通相对 bind mount、除 `.env` 外的 `env_file`、本地文件型 `configs` / `secrets`、`include` / `extends` 及项目外路径不支持首版远端部署，检查到即明确报错；Windows 本地绝对路径不可作为 VPS 挂载路径，远端绝对挂载路径须由用户预先准备。不要静默改变路径指向。
- `.env` 仅提供 Compose 变量插值；要将变量注入容器，Compose 服务须在 `environment` 显式引用变量，或使用 `env_file: .env`。预览仅展示脱敏摘要，绝不直接展示可能含密钥的 `docker compose config` 原文。

### 4.4 Tab: 环境变量

```
Card
|-- 分组 Select: [按主机] [项目通用]
|-- Key-Value 编辑列表: KEY | VALUE(可切换明文/掩码) | 敏感[默认开启] | [删除行]
|-- [+] 添加变量      [保存]
|-- 提示条 (muted): "部署时写入远端 .env（权限 600），不纳入镜像"
```

- VALUE 默认掩码显示（`text-sm` 圆点），创建时点击眼睛图标可临时查看。敏感开关默认开启；关闭前提醒此值将以非秘密配置写入 SQLite。
- 敏感变量仅创建时可查看，其值保存在操作系统凭据管理器；SQLite 只存引用。若凭据管理器不可用，禁止保存敏感变量，不退回明文。明文日志、发布历史与配置预览中均不得出现变量值。
- 主机专属值覆盖项目通用值；重复键或保留键 `DEVINGPANEL_IMAGE` 在保存时提示冲突。发布时生成的 `.env` 仅放在版本化部署目录，权限 600，回滚前必须确认对应历史密钥仍可取回。

### 4.5 Tab: 目标主机

```
Card
|-- Table: 顺序/上移/下移 | 勾选 | 状态点 | 主机名 | 地址 | 分组
|-- 数据源: 所选主机组的主机列表；项目绑定的主机勾选（未分组主机视为同一组）
|-- 底部说明 (muted): "发布时按列表顺序逐台部署，健康检查通过后进入下一台"
```

首次绑定时先选主机组；只能勾选同组主机。勾选后可调整发布顺序；默认顺序是勾选顺序，发布页"更改"复用这个有序列表。项目未绑定主机、未选择部署服务或合并校验失败时，[发布] 禁用并显示原因。

### 4.6 Tab: 发布历史

该项目维度的发布记录 Table：时间 | 发布标识 | 目标主机数 | 结果 | 耗时 | 操作([详情])。
点击详情跳转发布页对应记录。最近 20 条，分页 `Previous / Next`。

历史通过不可变项目 ID 关联，不以可编辑的项目名称关联；改名不影响项目历史，删除后重建同名项目不得继承旧历史。每页最多 20 条，页码及上一页/下一页的可用状态由实际记录数计算。
