# P2 主机列表 / 主机详情 设计文档

> 需求映射：H-1 添加编辑删除、H-2 连接测试、H-3 主机分组、H-4 凭据加密、S-1/S-2 资源监控

## 1. 页面目的

管理 VPS 连接配置；查看单台主机详情与实时资源监控；作为容器管理的入口。

## 2. 入口

- 侧边栏"主机"；Dashboard 主机卡片点击进入详情。

### 3.2 添加 / 编辑主机 Dialog（sm:max-w-lg）

表单字段：

| 字段 | 控件 | 校验 |
|------|------|------|
| 名称 | Input | 可空，默认使用地址；复制主机时预填“原名 副本” |
| 地址 | Input (mono) | 必填，IP 或域名 |
| SSH 端口 | Input number | 默认 22 |
| 用户名 | Input | 默认 root |
| 认证方式 | 分段单选：密码 / 使用凭据 / 无密码 | 必选 |
| 密码 / 凭据 | Password Input 或 Textarea (mono) | 按认证方式显示；无密码时隐藏 |
| 连接方式 | 直接连接 / SSH 跳板 / 代理连接 | 跳板可按顺序选择多台已配置主机；代理支持 HTTP CONNECT、SOCKS5 |
| 分组 | Select + 新建分组按钮 | 可空 |
| 备注 | Textarea | 可空 |

底部按钮：`[测试连接]` (variant=outline) + `[保存]` (variant=default)。
测试连接：按钮进入 loading，成功变 success 文案"连接成功，Docker 已就绪"，失败显示 destructive 错误原因。
首次连接或主机指纹未知时，测试先显示 SSH 主机指纹（SHA256）及"请通过独立渠道核对"提示，用户确认后记录并继续测试；已记录指纹发生变化时阻断连接，显示旧/新指纹，核实后通过明确的"更新可信指纹"操作重新连接，绝不自动接受。
保存后密码和可容纳的私钥交由操作系统凭据管理器保存；超过 MyGo Secrets 单项上限（2560 字节）的私钥保存在本机加密文件中，加密密钥交由凭据管理器保存，SQLite 只存引用。界面不回显明文（编辑时显示"已安全保存，留空则不修改"）。系统无法提供安全存储时阻止保存并显示配置指引，不将私钥降级为明文文件。
代理地址、端口和可选用户名作为连接配置保存；代理密码按同一凭据规则保存。跳板列表不得包含当前主机、重复主机或形成循环。测试连接时每台跳板和目标主机分别核对 SSH 指纹；代理连接也必须核对目标指纹。代理鉴权失败、跳板失败与目标主机失败分别提示，不能当作 Docker 不可用。

主机列表与详情的 [连接] 打开交互式 SSH 终端。正式桌面客户端在认证和指纹核对后创建远端 PTY，转发输入、输出和窗口尺寸；断线时结束会话并显示原因。WebUI 原型只模拟提示和输入，不执行远端命令。

[管理分组] 弹窗列出组名与主机数量，支持创建、重命名和删除；“未分组”为保留名称，重名被拒绝。已有项目 YAML 目标引用某分组时，变更组名或删除须先处理引用，不能让项目目标静默失效。复制主机沿用非秘密连接字段并要求重新核对凭据及指纹。

### 3.3 状态

- 加载：表格 Skeleton。空态：EmptyState"还没有主机" + [添加主机]。
- 删除：AlertDialog 二次确认，文案说明只删除本地配置和凭据，不影响 VPS；历史记录保留，但该主机的核实和回滚不可再执行。仅当该主机有正在执行的发布、回滚任务或活跃发布批次时拒绝删除。

### 4.3 Docker 安装引导（新增）

SSH 认证与主机指纹验证成功、但 `docker` 命令不存在时，不把主机笼统标为“连接失败”：显示“SSH 已连接 · Docker 未安装”，保留系统版本和架构，监控/发布继续不可用。命令存在但 daemon 不可用或当前用户无权限时显示实际错误，不能误导为未安装。主机详情“基本信息”卡片内提供与原型卡片风格一致的警告区和安装入口；主机列表状态可点击进入详情。

```
基本信息 Card
|-- [warning] SSH 已连接，Docker 未安装；发布和容器管理暂不可用
|-- 系统 Debian 13 / linux/amd64  ·  登录用户 root
|-- [一键安装 Docker] → 确认弹窗选择腾讯云镜像或官方源并查看将执行的步骤
```

一键安装仅在已确认 SSH 指纹、受支持的 Debian 13、root 登录、apt/dpkg/systemd 可用且 Docker 未安装时启用；其他系统提供人工安装指引，不执行未知发行版脚本。确认弹窗必须列出 apt 源域名、Docker 官方 GPG 指纹、拟安装的 Engine/CLI/containerd/Buildx/Compose 包、可能的服务启动与磁盘/网络影响。用户明确确认后才执行；安装中锁定重复点击并显示当前阶段，失败保留可读原因和人工修复方式；中途断线或退出客户端须人工核对，不自动重试。成功须重新核对 Docker daemon、Compose、架构及本机 Unix socket，不能只按 apt 退出码宣称就绪。不会通过 `curl | sh` 执行第三方脚本，不自动移除已有包或覆盖现有 Docker 配置。

国内源使用固定的腾讯云 Docker CE Debian apt 镜像；官方源为显式备选。下载的仓库密钥需核对 Docker 官方 GPG 指纹，再以 `Signed-By` 限制到专用源文件；apt 本身验证仓库签名。源不可达或签名不符立即停止，不静默切换源。Docker Hub 镜像加速与软件包源是两回事：本产品的业务镜像默认由本机 `save → SFTP → load`，不依赖 VPS 拉 Docker Hub；若 Compose 引用了其他公共镜像，需由用户提供可信的私有 Registry 或云厂商专属加速地址，经明确确认后另行配置，不预置不明公共代理。

对 Docker 五个包写入专用 apt preferences（优先级 990，不强制降级已装包），更新源后检查候选版本确实来自所选仓库，否则在安装包前停止；`apt-get update` 使用 `APT::Update::Error-Mode=any`，不能将镜像源下载失败后的旧缓存视作成功。安装前还需核对 root、apt/dpkg/curl、运行中的 systemd 与至少 2 GiB 根目录空间。中断或半安装不自动再次执行，由用户核对专用 `.sources`、`.pref`、密钥和包状态。

### 4.4 Docker Hub 镜像源配置

Docker 已连接且 root/指纹已确认的主机，在“基本信息”卡片下展示 Docker Hub 镜像源区块和 [配置镜像源]。点击后弹窗显示经当前 VPS 实测的 1Panel、DaoCloud 两个地址，明确说明只替换 `registry-mirrors`、保留其他 daemon 设置、重启 Docker 及公共代理的隐私/内容风险。用户确认前不修改；存在运行中容器时阻断重启。若配置和 daemon 已一致则直接报告“无需重启”。

客户端读取现有 `/etc/docker/daemon.json`（限 64 KiB）并解析为 JSON 对象；无效文件、符号链接或其他非普通文件一律阻断。生成合并配置后经随机私有临时文件写入，使用 `dockerd --validate` 校验；以 `/etc/docker/.devingpanel-mirror.lock` 阻断本应用并发操作，提交前重查原文件摘要与容器状态。原文件备份后原子替换，重启并核对 `docker info` 中的镜像源。明确失败时尝试恢复原文件并重启；超时/断线结果不明则保留备份与锁并提示人工核实，不盲目重试。外部管理员/工具不遵守此锁时仍可能并发修改，须协调维护窗口。安装 Docker 的流程不静默配置第三方镜像源，此入口独立且需确认。其他公共源仅因用户提供而作为候选，未通过实机拉取的不写入默认值。
