# P1 总览 Dashboard 设计文档

> 需求映射：H-1/H-2 主机在线状态、B-5 Docker 环境检测、S-1 资源概览、D-5 部署历史、易用性"三步完成核心流程"

## 1. 页面目的

打开客户端的第一屏：一眼看到所有 VPS 的在线状态与资源水位、本地 Docker 环境是否可用，并提供"去发布"的核心动作入口。

## 2. 入口

- 侧边栏"总览"，应用启动默认页。

## 3. 布局

```
内容区
|
|-- ① 页头
|   标题 "总览"  右侧: [去发布] (variant=default, 链接到发布页)
|
|-- ② 本地环境卡 (Card, 通栏)
|   左: Docker 状态点 + "本地 Docker 可用 / 未检测到 Docker"
|   右: [检测说明] 链接 (不可用时显示, 指引安装)
|
|-- ③ 主机概览卡片区 (grid grid-cols-1 md:grid-cols-2 xl:grid-cols-3 gap-4)
|   每台 VPS 一张紧凑 Card:
|   +--------------------------------------+
|   | ● myapp-prod-1        1.2.3.4        |  在线点 + 别名 + IP(mono)
|   | CPU ▓▓▓░░ 42%   内存 ▓▓░░░ 61%       |  细进度条 + 百分比
|   | 容器 5 运行    磁盘 38%              |
|   +--------------------------------------+
|   卡片点击 -> 进入主机详情页
|   超过 8 台时滚动 (卡片区 max-h 固定)
|
|-- ④ 最近发布 (Card)
|   最近 5 条发布记录: 时间 | 项目 | 发布标识 | 结果 Badge | 耗时
|   底部 "查看全部" 链接 -> 发布历史页
```

## 4. 组件清单

| 区域 | 组件 |
|------|------|
| 页头 | 页面标题 + Button("去发布") |
| 环境卡 | Card + 状态圆点 + 链接 Button(variant=link) |
| 主机卡片区 | Card x N；内部 Progress(细, h-1.5) + 等宽字体 IP |
| 最近发布 | Table（无边框，行间 border-b）+ Badge |

## 5. 状态

| 状态 | 表现 |
|------|------|
| 加载 | 主机卡片 3 个 Skeleton；最近发布 5 行 Skeleton |
| 无主机 | ③ 区显示 EmptyState："添加你的第一台 VPS" + [添加主机] 按钮 |
| 主机离线 | 卡片状态点 destructive 色，CPU/内存显示 "--"，卡片整体不置灰 |
| 无发布记录 | ④ 区显示 muted 文案"暂无发布记录" |
| Docker 不可用 | 环境卡状态点 destructive，显示安装指引链接 |
| P0 未上线资源监控 | 主机卡只显示在线状态、地址和 Docker 连通性；CPU/内存/磁盘及容器数在 P1 上线后才展示，不用虚构数值占位 |

## 6. 交互

- P0 进入页面时检测主机连接；P1 上线后才拉取资源数据并每 30s 刷新（不打断用户滚动）。
- 卡片 hover `border-ring` 轻微强调，点击进主机详情。
- "去发布"跳转发布页；若未配置任何项目，发布页展示空态引导。
