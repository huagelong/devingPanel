# P1 总览 Dashboard 设计文档

> 需求映射：H-1/H-2 主机在线状态、B-5 Docker 环境检测、S-1 资源概览、D-5 部署历史、易用性"三步完成核心流程"

## 1. 页面目的

打开客户端的第一屏：一眼看到所有 VPS 的在线状态与资源水位，通过顶部栏查看本地 Docker 状态，并提供“去发布”的核心动作入口。

## 2. 入口

- 侧边栏"总览"，应用启动默认页。

## 3. 布局

```text
总览                                               [去发布]
页面说明
[ 在线主机 2/3 ] | [ 已配置项目 1 ] | [ 运行容器 9 ] | [ 最近发布 ● 成功 ]
需要处理：离线主机 / 各项目最新发布的失败或未验证状态
当前发布任务（运行或暂停时出现）                 [继续查看]

最近发布（主区）                    主机概览（辅助区）
时间 / 项目 / 标识 / 目标 / 结果 / 耗时 / 操作   名称、状态、地址、容器数
[查看全部]                          CPU / 内存 / 磁盘 + 水位条
                                   [查看全部主机]
项目状态（主区）
项目 / 本地路径 / 目标 / 状态 / 操作
[全部项目]
```

顶部 4 栏状态摘要条展示在线主机数、已配置项目数（含就绪数）、运行容器数与均值水位（P0 显示 Docker 环境）以及最近发布结果。主列由“最近发布”和“项目状态”组成（均带 1px 边框容器）；主机概览使用 304px 辅助列。1279px 及以下先展示主列，再展示主机概览。辅助区使用轻微中性色底与 1px 边框，主机之间以间距和分隔线区分，不为每台主机再套卡片。超过 8 台时列表限高滚动。

需要处理区只在有内容时出现：离线主机可进入详情；发布提醒按不可变项目 ID 取时间最新的记录，只展示失败或 warning 结果。较早失败不会覆盖较新成功。最多直接显示 4 项，其余给出数量及主机、发布历史入口。提醒描述的是连接或发布结果，不等同于实时故障诊断。

运行或暂停的当前发布提供返回执行页的入口；展示任务保存的项目名、标识和状态，区分进行中、暂停与待核实；停留在总览时也随任务结束清除入口并刷新最近结果。页面预览为空时不显示任务或提醒。

## 4. 组件与层级

页头保留“去发布”主按钮。需要处理区使用语义警告色，活动表使用完整行分隔；主机概览复用 Badge 与等宽地址。表格与主机区不再共用等权重的大卡片结构。

## 5. 状态

| 状态 | 表现 |
|------|------|
| 加载 | 主机卡片 3 个 Skeleton；最近发布 5 行 Skeleton |
| 无主机 | 主机概览区显示 EmptyState：“添加你的第一台 VPS” + [添加主机] 按钮 |
| 主机离线 | 状态 Badge 使用 destructive 色，CPU/内存/磁盘显示 "--"，主机条目整体不置灰 |
| 无发布记录 | 最近发布区显示 muted 文案“暂无发布记录” |
| Docker 不可用 | 顶栏显示不可用状态，内容区切换为本机 Docker 安装引导及重新检测入口；总览暂不显示 |
| P0 未上线资源监控 | 主机条目只显示在线状态、地址和 Docker 连通性；CPU/内存/磁盘及容器数在 P1 上线后才展示，不用虚构数值占位 |

## 6. 交互

- P0 展示主机连接状态；P1 上线后展示资源数据。数据来源与刷新间隔见 `docs/technical-architecture.md`，刷新不打断用户滚动。
- 主机条目悬停强调名称，点击进入主机详情。
- "去发布"跳转发布页；若未配置任何项目，发布页展示空态引导。

## 窄窗口原型

最近发布在 1023px 及以下按记录分组，时间、项目、发布标识、结果与耗时分别显示字段名；保留桌面表格列集，不要求用户横滚寻找结果。
